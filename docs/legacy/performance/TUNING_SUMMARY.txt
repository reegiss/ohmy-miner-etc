┌──────────────────────────────────────────────────────────────────────────────┐
│ ✨ TAKEAWAYS & LESSONS LEARNED                                               │
└──────────────────────────────────────────────────────────────────────────────┘

  1. Smaller batches ≠ Worse
     ├─ Common misconception refuted by data
     └─ Register pressure dominates over launch overhead

  2. Architecture matters
     ├─ sm_75 (Turing) has specific register constraints
     ├─ NONCES=1 hits sweet spot for occupancy
     └─ May differ on other GPU architectures

  3. Empirical data > Assumptions
     ├─ 13 test points reveal true scaling curve
     ├─ Monotonic degradation with larger batches
     └─ Local memory spill is invisible without profiling

  4. Occupancy is king
     ├─ More independent warps = better scheduling
     ├─ Fewer registers/thread = more warps fit per SM
     └─ ILP hidden by latency can't overcome occupancy loss

  5. Real validation matters
     ├─ Benchmark proves local behavior
     ├─ Pool test proves real-world stability
     └─ Combined validation = confidence
